调试与训练指南
============================

在本教程中，我们将指导使用 Isaac Lab 的开发者了解各种参数对训练时间、GPU 利用率和
内存用量的影响。
这对解决强化学习（RL）训练中常见的内存不足（Out of Memory，OOM）错误尤其有帮助。
我们将讨论在 Isaac Lab 中进行 RL 训练时常见的错误，并提供一些故障排查步骤的指导。


使用并行环境进行训练
-----------------------------------

Isaac Lab 的核心 RL 范式是使用大量环境并行训练。
这里，我们将环境定义为在仿真中与其他机器人或对象交互的单个机器人或多个机器人的实例。
通过并行创建多个环境，我们会生成环境的多个副本，使每个环境中的机器人能够独立于其他环境探索世界。
因此，环境的数量成为训练的一个重要超参数。
一般来说，并行运行的环境越多，我们在 rollout 期间能收集的数据就越多，
这反过来又为 RL 训练提供了更多数据，由于 RL 智能体可以从并行经验中学习，因此训练速度也更快。

然而，环境的数量也可能受到其他因素的限制。
内存通常是我们能并行运行的环境数量的硬性约束。
当向世界中添加更多环境时，仿真也需要更多内存来表示和模拟场景中的每个对象。
因此，我们能并行仿真的环境数量通常取决于机器上可用的内存资源量。
此外，不同形式的仿真也会消耗不同数量的内存。
例如，具有高保真视觉和碰撞网格的对象会比简单的几何图元消耗更多内存。
可变形体的仿真也可能比刚体需要更多内存。

带渲染的训练通常比仅运行物理仿真消耗更多的内存。在分辨率相对较大时进行渲染尤其如此。
此外，在使用图像观测训练 RL 策略时，我们通常也需要更多内存来保存图像缓冲区的 rollout
轨迹以及更大的策略网络。这两个部分也会影响可用于仿真的内存量。

为了减少内存消耗，一种方法是在可能的情况下简化资产的碰撞网格，只保留正确仿真接触所需的
最基本碰撞形状。
此外，我们建议仅在使用少量环境进行调试时才开启视口（viewport）。
在并行训练大量环境时，建议以无头（headless）模式运行，以避免任何渲染开销。
如果 RL 流水线需要在循环中进行渲染，请务必减少环境的数量，同时考虑图像缓冲区的尺寸
和策略网络的大小。当遇到内存不足错误时，最简单的解决方法可能是减少环境的数量。


超参数调优
---------------------

虽然在许多情况下，并行仿真更多的环境可以带来更快的训练和更好的结果，但也存在这样的情况：
当环境数量达到某个阈值时，收益会递减。
该阈值会因环境、任务、策略设置和 RL 算法的复杂程度而异。
当并行仿真的环境更多时，每个仿真步骤需要更多时间来完成仿真，这会影响整体训练时间。
当环境数量较少时，每步仿真时间的增加与从更多经验中获得的训练性能提升相比，通常微不足道。
然而，当环境数量达到一定程度后，为 RL 算法提供更多经验的好处可能开始饱和，
而增加的仿真时间可能会超过训练性能方面的收益。

与环境数量过大导致收益递减相反，使用较少的环境进行训练也可能充满挑战。
这通常是由于 RL 策略无法获得足够的经验来学习。
要解决这个问题，增大批量大小（batch size）或时域长度（horizon length）可能会有所帮助，
以弥补因并行环境较少而收集到的数据量不足的问题。
当环境数量受到可用资源限制时，使用多个 GPU 并行运行或跨多个节点训练也有助于缓解
因 rollout 有限而导致的问题。


训练期间调试 NaN
-------------------------------

RL 训练中常见的一个错误是观测缓冲区中出现 NaN，这些 NaN 往往会传播到策略网络中，
导致下游训练流水线崩溃。
在大多数情况下，NaN 的出现发生在仿真变得不稳定时。
这可能是由于施加在机器人上的动作过于剧烈，超出了仿真的限制，或者是资产被重置到无效状态。
一些有助于减少 NaN 出现的技巧包括：适当调整资产的物理参数，确保关节、速度和力的限制
处于合理范围内，并且机器人的增益已正确调优。
此外，最好检查施加在机器人上的动作是否合理，不会对物体施加过大的力或冲量。
减小物理仿真的时间步长也有助于提高仿真的精度和稳定性，此外还可以增加求解器迭代次数。


理解训练输出
------------------------------

每个 RL 库在训练期间都会生成自己的输出数据。
一些库的输出较为详细，生成的日志包含有关训练过程的更详细信息，而另一些库则更为紧凑。
在本节中，我们将解释各个 RL 库的常见输出。


RL-Games
^^^^^^^^

在每次迭代中，RL-Games 会打印数据收集、推理和训练性能的统计信息。

.. code:: bash

  fps step: 112918 fps step and policy inference: 104337 fps total: 78179 epoch: 1/150 frames: 0

``fps step`` 指环境步进的 FPS，其中包括应用动作、计算观测、奖励、结束标志（dones）
和重置，以及推进仿真。

``step and policy inference`` 测量 ``fps step`` 中包含的所有内容，
再加上策略推理计算动作所需的时间。

``fps total`` 测量上述所有内容以及训练迭代所需的时间。

它会按指定的时间间隔记录当前最佳奖励以及保存到文件的中间检查点的路径。

.. code:: bash

  => saving checkpoint 'IsaacLab/logs/rl_games/cartpole_direct/2024-12-28_20-23-06/nn/last_cartpole_direct_ep_150_rew_294.18793.pth'
  saving next best rewards:  [294.18793]


RSL RL
^^^^^^

在每次迭代中，RSL RL 会提供以下输出：

.. code:: bash

                          Learning iteration 0/150

                       Computation: 50355 steps/s (collection: 1.106s, learning 0.195s)
               Value function loss: 22.0539
                    Surrogate loss: -0.0086
             Mean action noise std: 1.00
                       Mean reward: -5.49
               Mean episode length: 15.79
  --------------------------------------------------------------------------------
                   Total timesteps: 65536
                    Iteration time: 1.30s
                        Total time: 1.30s
                               ETA: 195.2s


该输出涵盖了数据收集、推理和学习的总 FPS，以及收集时间和学习时间在每步上的细分。
此外，还提供了训练损失的统计数据，以及当前的平均奖励和回合长度。

在底部的部分，它记录了迄今为止已完成的总步数、当前迭代的总迭代时间、
整体训练总时间，以及完成全部迭代所需的预计训练时间。


SKRL
^^^^

SKRL 提供了非常简洁的输出，以总时间步数（除以环境数量）的百分比显示训练进度。
它还包括到目前为止已用的总时间和完成训练的预计时间。

.. code:: bash

    0%|                                          | 2/4800 [00:00<10:02,  7.96it/s]


Stable-Baselines3
^^^^^^^^^^^^^^^^^

Stable-Baselines3 提供了详细的输出，概述了 rollout 统计数据、计时信息和策略数据。

.. code:: bash

  ------------------------------------------
  | rollout/                |              |
  |    ep_len_mean          | 30.8         |
  |    ep_rew_mean          | 2.87         |
  | time/                   |              |
  |    fps                  | 8824         |
  |    iterations           | 2            |
  |    time_elapsed         | 14           |
  |    total_timesteps      | 131072       |
  | train/                  |              |
  |    approx_kl            | 0.0079056695 |
  |    clip_fraction        | 0.0842       |
  |    clip_range           | 0.2          |
  |    entropy_loss         | -1.42        |
  |    explained_variance   | 0.0344       |
  |    learning_rate        | 0.0003       |
  |    loss                 | 10.4         |
  |    n_updates            | 20           |
  |    policy_gradient_loss | -0.0119      |
  |    std                  | 1            |
  |    value_loss           | 17           |
  ------------------------------------------

在 ``rollout/`` 部分，会记录该迭代的平均回合长度和奖励。在 ``time/`` 部分，
提供了总 FPS、迭代次数、已用总时间和总时间步数的数据。最后，在 ``train/`` 部分，
记录了训练参数的统计数据，例如 KL、损失、学习率等。
